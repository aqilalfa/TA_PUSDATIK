**4.2 Implementasi**

Implementasi sistem pada penelitian ini difokuskan pada penyusunan alur autentikasi yang aman, terstruktur, dan mudah dipelihara. Secara umum, arsitektur aplikasi menempatkan FastAPI sebagai lapisan layanan utama yang menangani permintaan autentikasi, penerbitan token, serta pengelolaan sesi pengguna. Seluruh proses tersebut dipusatkan pada komponen autentikasi yang terdapat di `backend/app/auth/` dan rute API yang didefinisikan pada `backend/app/api/auth_routes.py`.

Pada sisi integrasi direktori, `LDAPDirectoryClient` bertugas melakukan koneksi ke server LDAP, melakukan bind menggunakan kredensial pengguna, serta membaca atribut yang dibutuhkan oleh aplikasi. Atribut seperti nama tampilan, surel, unit kerja, identitas pegawai, dan keanggotaan grup digunakan sebagai dasar untuk membangun identitas lokal pengguna. Dengan pendekatan ini, sistem tidak perlu menyimpan kata sandi direktori, tetapi tetap dapat mengenali pengguna berdasarkan data yang valid dari sumber identitas eksternal.

Setelah autentikasi berhasil, `LDAPAuthProvider._upsert_shadow_user()` berfungsi membentuk atau memperbarui shadow user pada basis data lokal. Mekanisme ini penting karena aplikasi tetap membutuhkan representasi pengguna di level internal untuk keperluan otorisasi, pencatatan audit, dan pemetaan peran. Pendekatan shadow user memungkinkan data identitas tetap tersinkronisasi tanpa mengorbankan keamanan kredensial LDAP.

Pemetaan peran dilakukan melalui `role_mapper.py`. Modul ini mengonversi nama grup LDAP menjadi role aplikasi yang lebih sederhana dan konsisten. Proses tersebut dimaksudkan agar role internal dapat dikelola secara terpusat melalui konstanta `DEFAULT_ROLE_MAPPING`, sehingga perubahan kebijakan akses dapat dilakukan tanpa menyentuh logika autentikasi inti.

Pada lapisan sesi, `jwt_manager.py` digunakan untuk membentuk access token dan refresh token dengan algoritma HS256. Access token berlaku dalam jangka waktu pendek, sedangkan refresh token disimpan dalam cookie HttpOnly agar tidak mudah diakses oleh skrip sisi klien. Untuk proses logout, token yang aktif saat ini dimasukkan ke dalam blacklist berbasis basis data. Walaupun pendekatan ini sudah memadai untuk tahap pengembangan, rancangan lanjutan yang lebih sesuai untuk produksi adalah memindahkan blacklist tersebut ke Redis agar lebih efisien dan mudah dikelola.

Untuk mendukung pengujian terhadap LDAP nyata, repositori ini juga menyediakan `docker-compose.ldap.yml` dan berkas bootstrap LDIF. Kombinasi tersebut memungkinkan penyediaan lingkungan OpenLDAP lokal yang dapat digunakan untuk pengujian integrasi tanpa harus bergantung pada infrastruktur eksternal.

def authenticate(self, username: str, password: str) -> dict[str, Any] | None:
	connection = Connection(server, user=user_dn, password=password, raise_exceptions=True, auto_bind=True)
	connection.search(..., attributes=["memberOf", "department", "displayName", "mail", "employeeID"])
	entry = connection.entries[0]
	groups = [str(group).split(",")[0].replace("CN=", "") for group in entry.memberOf.values]
	return {"username": username, "display_name": str(entry.displayName), "email": str(entry.mail), "groups": groups}

def _upsert_shadow_user(self, db: Session, directory_user: dict, roles: list[str]) -> User:
	email = directory_user.get("email")
	user = db.query(User).filter(User.email == email).first()
	if user is None:
		user = User(email=email, name=directory_user.get("display_name") or email)
	user.roles = serialize_roles(roles)
	db.add(user)
	db.commit()
	db.refresh(user)
