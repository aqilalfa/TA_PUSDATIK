**4.4 Integrasi LDAP**

Integrasi LDAP dalam penelitian ini dirancang sebagai mekanisme otentikasi eksternal yang menjadi fondasi untuk identitas pengguna di dalam aplikasi. Pendekatan yang digunakan menempatkan direktori LDAP sebagai sumber kebenaran utama bagi kredensial, sedangkan sistem aplikasi bertindak sebagai konsumen identitas yang mengelola otorisasi internal melalui shadow user dan role lokal.

Komponen inti pada integrasi ini adalah `LDAPDirectoryClient`. Modul tersebut bertanggung jawab melakukan koneksi ke server LDAP, melakukan bind, menjalankan pencarian atribut, serta menangani retry apabila koneksi mengalami kegagalan sementara. Melalui pendekatan ini, sistem dapat memperoleh informasi pengguna seperti nama tampilan, email, departemen, identitas pegawai, dan keanggotaan grup. Data tersebut kemudian menjadi dasar untuk pembentukan identitas internal yang konsisten.

Pada alur autentikasi, permintaan login diterima melalui endpoint `/login` pada `backend/app/api/auth_routes.py`. Selanjutnya, kredensial dikirim ke `LDAPDirectoryClient.authenticate(username, password)` untuk divalidasi terhadap direktori. Apabila autentikasi berhasil, `LDAPAuthProvider._upsert_shadow_user()` memperbarui atau membuat pengguna lokal, kemudian `role_mapper.map_directory_groups_to_roles()` menerjemahkan grup LDAP menjadi role aplikasi. Setelah itu, `JWTManager` membentuk access token dan refresh token sebagai representasi sesi pengguna.

Proses ini juga didukung oleh mekanisme logout yang melakukan blacklist terhadap token aktif. Pada implementasi saat ini, token yang telah dipakai untuk logout disimpan ke dalam tabel blacklist sehingga token yang sama tidak dapat digunakan kembali hingga masa kedaluwarsanya habis. Walaupun mekanisme ini masih berbasis basis data, struktur tersebut sudah cukup untuk mendukung validasi fungsional di tahap pengembangan.

Pengujian integrasi disusun agar dapat dijalankan baik pada lingkungan mock maupun lingkungan LDAP nyata. Untuk skenario nyata, `docker-compose.ldap.yml` dan berkas `ldap_bootstrap.ldif` disediakan agar OpenLDAP lokal dapat digunakan secara cepat. Untuk skenario mock, test memanfaatkan LDAP palsu yang meniru struktur direktori dan keanggotaan grup agar pengujian tetap deterministik.

Potongan kode berikut memperlihatkan inti proses login dan logout.

```python
user = authenticate_user(form_data.username, form_data.password, db)
access_token = jwt_manager.create_access_token(data={"sub": user.email, "roles": roles, "sid": session_id})
refresh_token = jwt_manager.create_refresh_token(data={"sub": user.email, "sid": session_id})
response.set_cookie(key="refresh_token", value=refresh_token, httponly=True, secure=cookie_secure)
```

```python
payload = jwt_manager.verify_token(token)
if payload and "jti" in payload:
	jti = payload["jti"]
	exp = datetime.fromtimestamp(payload["exp"], tz=timezone.utc)
	blacklist_entry = TokenBlacklist(jti=jti, expires_at=exp)
	db.add(blacklist_entry)
	db.commit()
response.delete_cookie("refresh_token")
```

Kutipan langsung dari test aktual memperkuat narasi integrasi tersebut.

> "Test LDAP provider authenticates against mock LDAP"

> "Test LDAP group mapping works for all test users"

> "Test first LDAP login creates shadow user"

> "Test subsequent LDAP login updates shadow user"

Keempat kutipan tersebut menunjukkan bahwa integrasi LDAP diuji secara menyeluruh, mulai dari autentikasi terhadap mock directory, validasi pemetaan grup, hingga lifecycle shadow user pada login pertama dan login berikutnya. Dengan demikian, implementasi yang dihasilkan tidak hanya bekerja pada level fungsional, tetapi juga konsisten terhadap perubahan data pengguna.
