**4.5 Evaluasi dan Diskusi**

Sub-bab ini membahas hasil yang diperoleh dari implementasi dan pengujian sistem, sekaligus memberikan interpretasi terhadap dampaknya pada skenario penggunaan yang lebih luas. Evaluasi dilakukan berdasarkan perilaku autentikasi, pengelolaan token, stabilitas koneksi LDAP, dan konsistensi pembentukan shadow user.

Secara umum, hasil pengujian menunjukkan bahwa alur autentikasi LDAP dapat berjalan dengan baik pada lingkungan mock maupun pada integrasi yang menyerupai kondisi nyata. Keberhasilan ini terlihat dari kemampuan sistem mengenali kredensial pengguna, memetakan grup ke role yang sesuai, serta menyimpan identitas internal secara konsisten. Stabilitas koneksi juga cukup baik karena mekanisme retry telah disiapkan pada `LDAPDirectoryClient` untuk mengurangi kegagalan akibat gangguan sementara.

Dalam hal otorisasi, penggunaan shadow user memberikan keuntungan karena aplikasi tetap memiliki representasi lokal pengguna tanpa harus menyimpan kata sandi direktori. Namun demikian, pendekatan ini menuntut sinkronisasi atribut yang cermat agar perubahan pada direktori LDAP tetap tercermin di aplikasi. Hasil pengujian menunjukkan bahwa pemetaan peran berbasis grup dapat bekerja dengan baik selama format DN diolah secara benar sebelum dicocokkan dengan mapping internal.

Pada aspek keamanan token, pengujian terhadap access token dan refresh token memperlihatkan bahwa sistem dapat membedakan token yang valid dan token yang kedaluwarsa. Proses logout juga berhasil menandai token agar tidak dapat digunakan kembali. Meskipun demikian, implementasi blacklist berbasis basis data masih lebih cocok untuk prototipe dibandingkan untuk skala produksi, sehingga penggunaan Redis tetap menjadi rekomendasi yang relevan untuk pengembangan lanjutan.

Adapun keterbatasan utama yang masih perlu diperhatikan terletak pada manajemen secret untuk algoritma HS256, pengelolaan ukuran file biner yang besar, serta kebutuhan untuk menambahkan pengujian beban dan audit keamanan yang lebih sistematis. Dari sudut pandang implementasi, hal-hal tersebut belum menghambat fungsi dasar sistem, tetapi tetap penting untuk diperbaiki sebelum sistem digunakan secara lebih luas.

Potongan berikut memperlihatkan skenario pengujian yang digunakan sebagai dasar evaluasi pada lapisan JWT dan autentikasi aplikasi.

```python
def test_create_and_verify_access_token():
	data = {"sub": "admin@bssn.go.id", "roles": ["admin_pusdatik"]}
	token = jwt_manager.create_access_token(data)
	payload = jwt_manager.verify_token(token)
	assert payload["sub"] == "admin@bssn.go.id"
```

```python
def test_login_valid_credentials(client):
	response = client.post(
		"/api/auth/login",
		data={"username": "admin@bssn.go.id", "password": "password123"}
	)
	assert response.status_code == 200
	assert "access_token" in response.json()
```

Kutipan langsung dari test autentikasi dan JWT memperkuat hasil evaluasi tersebut.

> "Test standard access token creation and verification"

> "Test that an expired token is rejected"

> "Test login with correct password returns access token and refresh cookie"

> "Test login with wrong password"

Kutipan pertama dan kedua menunjukkan bahwa validasi token mencakup kondisi normal dan kondisi gagal. Kutipan ketiga menegaskan bahwa login sukses harus menghasilkan access token sekaligus refresh cookie. Sementara itu, kutipan keempat memastikan jalur login gagal tetap menjadi bagian penting dalam pengujian regresi, sehingga implementasi tidak hanya valid pada kasus ideal, tetapi juga pada skenario kesalahan yang realistis.
